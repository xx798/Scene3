# HIA 定时诊断

原有扣子智能体、扣子工作流不变。新增任务类型 `hia_workflow`，无需数据库迁移。

1. 在定时任务页选择「HIA 工作流」，填写 HIA API 地址和该工作流的 API Key，参数填 `{"limit":0}`，配置 Cron 后保存。API 地址可以填写完整的 `/sync_run_app_workflow` 地址，也可填写 API 基础地址，系统会自动补齐路径。
2. API 地址保存在 `bot_id`，API Key 保存在 `workflow_id`，均不再读取 `.env.local`。任务查询接口不会返回真实密钥；编辑已有任务时只显示掩码，保留掩码表示不更换，输入新值表示更换。
3. 手动触发和定时触发共用执行、任务日志、诊断入库逻辑；入库数据进入现有历史记录和报告流程。

调用配置的 `/sync_run_app_workflow` 地址，使用 `Apikey` 请求头，`InputData` 为 JSON 字符串，`Debug=true`、`IsStream=false`。默认 300 秒超时，可设置 `HIA_TIMEOUT_MS`（最多 600000）。

优先读取有效结束输出，否则解析成功节点的嵌套 JSON（含循环）。拒绝未替换的 `{{...}}` 模板；同次执行内按摄像头和抓拍时间去重。只有明确的「当前无施工」消息才允许零条成功，空 `{}` 不算业务成功。中文抓拍时间按北京时间转换。

日志保存执行 ID、结果数量、已保存数量和诊断摘要，不保存原始节点（其中可能包含密钥、Cookie 和带令牌的图片链接）。图片 URL 作为业务字段仍写入诊断表，与现有报告链路一致，数据库和报告仅限授权人员访问。

密钥过期、HTTP 错误、解析失败、入库失败、超时都会显示失败；部分写入会标明数量。无自动重试，避免重复执行远端告警。手动中止/超时只停止本地等待，不能保证取消远端工作流。

现有综合异常规则保持不变：摄像头状态非正常，或风险项明确为「异常」时计入异常；「无法识别」保留在检查明细，不自动改写为「异常」。
